## The three litmus tests, applied

### 1. Every number is traceable

**Pass, and it is now a build gate rather than a promise.**

The page contains no typed figure of any kind. Every quantity it wants is named
as an evidence key and rendered by the strip that arrives at S3.3:

```
evidence.runs:    the-long-build, the-engine-run
evidence.figures: sessions, cacheRead, ledgerEntries
```

`cacheRead` is the one that carries the page's own argument — the whole first
paragraph says a context window is re-sent and therefore re-paid, and the
cache-read total is what that costs, measured rather than asserted.

Before this checkpoint the rule was enforced on one field. `evidenceKey` in
`src/content/schema.ts` refuses a value where a key belongs, so
`figures: ["3016.29"]` cannot be written. Nothing stopped the same number being
written into the sentence beside it, which is the easier mistake by a distance:
naming a key is something you have to remember to do, and writing the number is
what writing normally looks like.

`src/lib/figures.ts` closes that. `ordered()` runs it over every entry as the
build renders it, so it fails `npm run build`, not a linter someone can skip:

```
BREAK A — "It cut the bill by 23%." added to theIdea[4]

concepts/context-engineering.yaml: theIdea[4] types a percentage (23%) and a
count of two digits or more (23) into the prose. Every figure on this site is
recomputed from the run store — name a key in `evidence.figures` and let the
evidence strip render it, so it cannot go stale while the sentence still reads
fine.
```

Shapes refused: a currency amount, a percentage, a multiplier, a ratio, a
decimal, a thousands-separated number, and any count of two digits or more.
Skipped as not-prose: `tryIt[].command` (a session number in a command),
`inConductor.citations[].path`, and the URL fields.

**The gap, stated rather than papered over:** a single-digit count in a sentence
is not caught, because a single digit is also how `Astro 7` and `Part 3` are
written and the false positives would make the gate unusable. So "7 owner
approvals" would pass. That is a known hole in a shape check, not a claim of
completeness, and it is written into the header of `figures.ts` where the next
person to trust the gate will read it.

### 2. The failures are on the page

**Pass.** `theProblem` carries three, and the third is not generic — it is the
failure mode the mechanism section then answers:

> A prompt assembled by appending has a length limit somewhere, and when it is
> reached what gets dropped is whatever was appended last. Put the accumulated
> knowledge at the end, where it reads naturally, and the cap quietly deletes
> the one part that was supposed to compound — on the longest runs first,
> because those are the runs with the most to carry.

More to the point of this test, `inConductor` publishes a failure of Conductor's
own mechanism rather than only its design. The third mechanism paragraph says
the placeholder refusal was right *and* what it cost: being strict about a
placeholder means knowing a template from a value, and before the engine drew
that line a literal brace in a stage's notes passed the plan check and then
stopped a run at a stage boundary, with the refusal on stderr and nowhere anyone
was looking. It is cited at the line where the engine learned the distinction.

The duration of that run is in the engine's own source comment and is
deliberately **not** on the page: it is a figure, and a figure on this site
comes from the corpus or it does not appear.

### 3. A concept page is useful without Conductor

**Pass, and the structural half is now a build gate.**

Measured by deleting `inConductor` and reading what is left:

```
words without inConductor:        538
mentions of the tool in that text:  0
words in inConductor.mechanism:   276
```

538 words of `oneLine` + `theIdea` + `theProblem` stand alone: what a context
window costs and why, the three moves that spend it well, the discipline of
keeping the rendered prompt, and three ways it goes wrong. A reader who has
never heard of Conductor can take all of it somewhere else.

`schema.ts` already put `theIdea` first for this reason. `ordered()` now also
refuses the build when `theIdea` names the tool:

```
BREAK B — "Done well, Conductor makes none of this look clever."

concepts/context-engineering.yaml: theIdea[4] names Conductor. The idea has to
read for someone who has never heard of it — the mechanism belongs in
inConductor, which is the section a reader is allowed to skip.
```

Applied to `theIdea` only. `theProblem` is left to the writer's judgement — a
failure is sometimes clearest told as one that actually happened — and SPEC
Part III asks for the tool-free discipline on the idea specifically.
