S3.3 - the evidence strip, and the key that has nothing behind it
=================================================================

The component (SPEC Part II): a monospace band carrying the figures a page
cites, rendered from src/data/corpus.json, never hand-typed. Concept pages carry
it at the foot; articles and reports carry it inline under the standfirst,
because a long-form piece argues from its numbers and the reader should meet
them before the argument rather than after it.

  Every rate prints its denominator underneath it, on the page, not in a

  the footer names the commands rather than asserting provenance in prose.


2. A key the corpus does not have fails the build
-------------------------------------------------

  Replacing `ledgerEntries` with `softBreakRatio` in
  src/content/concepts/context-engineering.yaml:

  $ npm run build
  concepts/context-engineering.yaml: evidence.figures names "softBreakRatio",
  which is not in the corpus. Nothing on this site is typed in, so a key with no
  figure behind it is a claim with no evidence behind it. Run `npm run harvest`
  if the corpus is stale; otherwise the key is wrong.
    corpus-wide keys: costPerCheckpoint, costPerSession, costedSessions,
      totalBugsFiled, totalCacheRead, totalCheckpointsDone,
      totalCheckpointsPlanned, totalCostUsd, totalGatesGreen, totalGatesRed,
      totalGatesRun, totalLedgerEntries, totalOwnerApprovals, totalRepos,
      totalRollovers, totalRuns, totalSessions, totalSoftBreaks, totalTokensIn,
      totalTokensOut
    per-run keys:     bugsFiled, cacheRead, checkpointsDone, checkpointsTotal,
      costUsd, gatesGreen, gatesTotal, ledgerEntries, ownerApprovals,
      rollovers, sessions, softBreaks, tokensIn, tokensOut
    at resolveEvidence -> ordered -> callGetStaticPaths

  It fires from ordered(), which is to say from the index page that merely lists
  the entry - before the page a reader would have opened is built at all. The
  page does not render blank; it does not render.


3. And a run label the corpus does not publish
----------------------------------------------

  Replacing `the-engine-run` with `nine-streets` - the shape of the mistake
  somebody makes by reaching for the real name of a run:

  $ npm run build
  concepts/context-engineering.yaml: evidence.runs names "nine-streets", which
  the corpus does not publish. Either anonymise.json has no entry for that run -
  in which case it is excluded on purpose and cannot be cited - or the label is
  a typo. Published runs: the-abandoned-prototype, the-aborted-start,
  the-accounting-run, the-ci-cleanup, the-demo, the-engine-run,
  the-first-false-start, the-fleet-backlog, the-fleet-round,
  the-fleet-round-after, the-long-build, the-one-session-chore,
  the-orchestrator-core, the-rehearsal, the-second-false-start,
  the-second-feature, the-terminal-face, the-third-feature.

  That is the anonymisation rule and the evidence rule meeting: a run excluded
  from the corpus cannot be cited by content either, and the failure says which
  of the two reasons applies.

  src/content/concepts/context-engineering.yaml was restored from HEAD after
  each break; the working tree is clean.


4. One thing measured here that S3.4 has to build around
--------------------------------------------------------

  The failing build exits -1073740791 (0xC0000409) after a libuv assertion
  rather than exit 1. Non-zero, so a gate does catch it - but it is a crash
  signal, not a clean failure, and this repo already knew that a failed Astro
  build does not reliably exit 1. So the `evidence` gate at S3.4 is a plain Node
  script that checks staleness with `harvest --check` and scans content for
  cited keys itself, rather than a wrapper around `npm run build`.


5. Battery
----------

  $ npm run check     astro check 0 errors, 42 tests pass
  $ npm run build     10 pages, 63 annotations on 8 pages all resolve

  No `data-sk-edit` anywhere in the strip, and that is correct rather than
  missing: `evidence` is on every collection's omit list, so the editor has no
  field for it, and an annotation naming a field the form model lacks fails the
  build. There is nothing here for an owner to edit - editing a key does not
  produce a different number, it produces a failed build.
