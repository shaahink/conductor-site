## The three litmus tests (SPEC Part I)

**1. Every number is traceable.** Neither page types a figure. Concept 7 names
`totalRollovers`, `totalSoftBreaks`, `rollovers`, `softBreaks`; concept 8 names
`totalOwnerApprovals`, `ownerApprovals`. All six are recomputed by the harvest
from the run store and all six are checked by the gate above. The prose gate in
`test/collections.test.mjs` independently refuses a number of two digits or more
in any sentence on either page — it passes.

**2. The failures are on the page.** Concept 7's mechanism ends on the
measurement that forced a fix: because the rollover branch returns before the
verdict pass, nothing filled in a rolled-over session's commits, so every board
and report showed those sessions as having committed nothing while the
repository said otherwise — one was called idle after shipping a pull request.
It also carries the abort bug: without the reset, the loop's first status check
re-exited instantly, which from outside is indistinguishable from a clean
finish. Concept 8 carries the silent-notification failure — a run that said
nothing at all about notifications, leaving an operator unable to tell "nothing
happened" from "nothing can be delivered" — and the hand-kept obligation list
that went stale, which is why every queue entry is derived and none is stored.

**3. Useful without Conductor.** Delete `inConductor` from concept 7 and what
remains is an argument about where state has to live, why a boundary is the only
safe place to change anything, why absence is the most reliable signal a dead
process can leave, and why running out of room must not be filed as failure.
Delete it from concept 8 and what remains is the case that oversight is a stop
rather than a watcher, the too-few/too-many tradeoff with the "would anyone ever
say no" test, the three fields that make an entry a request, derived-not-stored,
and the empty command. Both `tryIt` lists open with something a reader can run
with nothing installed — `git reflog` and `gh pr status`.

## Two corrections carried against the plan

1. **SPEC Part IV concept 8 calls the notification lane "push-only".** It is
   not. `Integrations/TelegramService.cs:18` long-polls and handles
   inline-keyboard callbacks that write a control file the run loop consumes at
   the next session boundary, so a reply is an instruction rather than an
   acknowledgement. The page says so and cites the line.

   published runs: `the-long-build` 34 of 53, `the-terminal-face` 11,
   `the-second-feature` 6 — eleven runs have none at all. Concept 7 cites the
   two runs that carry the mass rather than implying an average.
