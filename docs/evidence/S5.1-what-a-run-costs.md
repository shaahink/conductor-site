## The waste, re-verified against `conductor money` as SPEC Part V asked

SPEC Part V article 1 carried `$51.98` and `23%` with a warning that both were hand-derived and had
never been re-measured. They now are, and they were close but not right.

`conductor money --run <run> --json` reports, for the run published as `the-fleet-backlog`, a
dearest stage of **$52.06 — 23.2% of the run — 10 sessions, 4 checkpoints**, the dearest of that
run's 13 stages. The hand figure was low by eight cents; the share was right to a tenth of a point.

The *reason* is confirmed from that run's own knowledge ledger (read-only, filtered by `run_id`):
five separate sessions re-measured a deploy provider's daily production-build allowance, recorded
that the reopening time had not drifted, declared an acceptance for work they could not start, and
exited without claiming. A sixth session, spawned after the window reopened, finished the stage in
minutes. Nothing failed — the engine had no way to express *wait*, which is the verb (`--blocked-until`)
that exists now. The ledger text names private repositories and is not quoted anywhere on the site
or in this file; the article describes the situation by shape.

Second published waste figure, from the same source: `the-abandoned-prototype`'s dearest stage cost
**$44.15 — 31.6% of the run — 3 sessions, 0 checkpoints closed**.

## The machinery this needed, and the guard that had to change

`scripts/harvest.mjs` now asks `conductor money --run <id> --json` once per published run
(`readMoney`, +9.5s on a harvest) and publishes seven per-run figures from it: `tokensPerCheckpoint`,
`costPerMillionTokens`, `cacheReadShare`, and the four `dearestStage*` keys. Plus one corpus-wide
SQL figure, `totalCacheReadShare` (98.3%), whose numerator and denominator are both already
published beside it.

`refuseBudgetShaped()` used to refuse budget-shaped *names* anywhere in the corpus, which also
refused the verb's own answers — so the figures SPEC Part VI rule 5 points at could never have been
published at all. It now tests the **source**: a budget-shaped key ships only if its `source` starts
`conductor money` or `conductor budget`. The source string is the claim the strip prints under the
number, so a figure lying about where it came from is already lying to a reader.

Two things the verb's output carries that never reach `corpus.json`: `plan` and `repo` (a plan's
real name and a path on this machine), and the stage labels. Dropped in `readMoney`.

## Gates the run-id rule bit on the way past

The first draft of `MONEY` embedded the run id prefix in each figure's `source`. The existing test
caught it before the commit:

```
AssertionError: corpus.json contains the run id 0031daaa. Runs are published under their
anonymise.json label; the id stays in the map.
```

The source is now the placeholder form `conductor money --run <run> --json`.

Four tests added (49 total, was 45): the same money-shaped key refused when it claims SQL and
accepted when it names the verb; every money-shaped figure in the *committed* corpus checked against
its source; and a run collected without a money block refused rather than published as zeros.

That third test proved red by mutation — `the-long-build.tokensPerCheckpoint.source` was rewritten
to `run.db, opened read-only`:

```
AssertionError: the-long-build.tokensPerCheckpoint is money-shaped but says it came from
run.db, opened read-only
```

`npm run harvest` restored it.
