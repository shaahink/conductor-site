# S6.1 — the anonymisation check, proven red and green

`npm run anonymity` (`scripts/anonymity.mjs`) reads `dist/` after a build and
looks for the things SPEC Part VI forbids. It is the only gate on this site
whose forbidden list cannot be committed, because committing it would publish
the names it exists to protect. The list is derived at check time from
`conductor history --json --limit 0` and from `docs/dev/FIELD-NOTES-*.md` when
they are present, and no derived string is ever written to disk or printed.

## Green, at head

```
$ npm run anonymity
anonymity: 36 built files carry none of 51 machine paths, 15 private names,
4 distinctive tokens, 41 three-word run-name phrases or 8 secret shapes — of
those, 10 vendored file(s) were checked for paths and secrets only, not for
names; NOT CHECKED for quoted prose: no docs/dev/FIELD-NOTES-*.md on this
machine, which is expected in CI because they are untracked — this run did not
test that half of the rule.
exit 0
```

The coverage sentence is not decoration. The field notes are untracked by
design, so on CI the quotation half of this rule will never run, and a check
that reported a clean pass for work it did not do would be the exact failure
this site is about. It says so on every run, green or red.

## Red, on purpose

A scratch page was written into `dist/` carrying one real private repository
name, three consecutive words of one real run's name, and a home-directory
path. The planting script lives in the OS temp directory, not in this
repository, and prints nothing about what it planted.

```
$ node <temp>/plant-redproof.mjs C:/code/conductor-site
planted: one real private repository name, three consecutive words of one real
run name, and one home-directory path. Contents deliberately not printed.

$ npm run anonymity
anonymity: 4 finding(s) in the built output.

  __redproof.html: a home directory on someone's machine — C·······\ (9 chars)
  __redproof.html: a private repository name — c···················1 (21 chars)
  __redproof.html: a private repository name — b······1 (8 chars)
  __redproof.html: wording from a run's real name — c···················1 (21 chars)

The match is redacted because a build log is published too. Re-run with
--reveal on a machine that is allowed to see it. NOT CHECKED for quoted prose:
[…]
exit 1
```

Four findings from three planted strings: the planted repository name contains
a second, shorter private repository name as a whole word, which the check
found without being told to look. The scratch page was deleted afterwards and
`dist/` is ignored by git, so nothing planted was ever staged.

Every match is redacted to first character, last character and length. That is
deliberate and it is the second half of the same rule: a CI log is a published
artefact, and a check that prints a client's name into one has leaked while
reporting a failure. `--reveal` exists for the owner's own machine.

## What holds it

`test/anonymity.test.mjs`, twelve tests, all pure — no store, no build — so the
rule stays tested on a machine that has never seen a run:

```
$ node --test test/anonymity.test.mjs
✔ this site's own run is not treated as private
✔ a private repository's name, path, store and id are all forbidden
✔ a public repository is never listed as a private name
✔ run names are not a token source, because they are English
✔ the published vocabulary allowlists itself
✔ a private name planted in a page is found
✔ a finding is redacted, and the redaction is not the name
✔ matching is on whole words, so a substring is not a finding
✔ three consecutive words of a real run name are a finding
✔ field-note prose is caught at eight words, and paraphrase is not
✔ secret shapes are caught wherever they appear
✔ vendored bundles are checked for secrets but not for names
ℹ pass 12  ℹ fail 0
```

Its fixtures name a repository called `harrowgate-linens` and a run called
`harrowgate linens seasonal rebuild`. Both are invented. A test for a privacy
rule that ships real names in its fixtures has broken the rule in order to
check it.

## Two design decisions worth recording

**Names are matched whole; syllables are not.** The first working version
derived tokens from every private string including plan file names and run
names, and reported 106 findings on a clean build — every one of them an
ordinary English word that also appeared in somebody's plan title (`graph`,
`public`, `none`, `sums`). A check that cries wolf a hundred times is switched
off by its third run, which is a worse outcome than never having written it.
Tokens now come only from private repository names, which are identities; run
names are covered by matching three consecutive words, which is distinctive
enough to be a quotation rather than a coincidence.

**Vendored bundles are checked for secrets, not for names.** A minified bundle
from the kit is full of ordinary English identifiers, so name-matching against
it is all noise. Paths, run ids and secret shapes are still looked for there,
because a token in a vendored file is a leak wherever it came from. The count
of files given the narrower treatment is printed on every run rather than
quietly dropped.
