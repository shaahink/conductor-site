# S6.3 — Report C, the engine run

`src/content/reports/the-engine-run.yaml`, published at `/runs/the-engine-run/`.
Seven sections, thirteen evidence keys, one cited run and one cited window. No
figure typed into prose.

## What the read-only probe found

The store was opened `readOnly: true` and every string field longer than twelve
characters was redacted before printing, so no stage or checkpoint title entered
the session.

- **81 gates run, 72 green, 9 red.** The corpus total for red gates is 29, so
  **nearly a third of every gate failure in the whole corpus is in this one
  run** — a run that closed every checkpoint it opened. `runsWithARedGate` is
  6 of 18.
- **Exit codes:** `0` ×72, `-1073741502` ×4, `1` ×3, `3` ×1, `2` ×1. The corpus
  totals are `1` ×23, `2` ×1, `3` ×1, crash ×4 — so this run holds the corpus's
  only exit-2, its only exit-3, and **all four crashed gates**. Every failure
  status in the store other than the plain one is here.
- **The crashes ran for 21–178 ms** against a gate that takes minutes when it
  works. They did not fail; they never started.
- **Four distinct gates by duration.** The evaluation gate passes in 466–803 s
  (roughly eight to thirteen minutes); the build gate beside it in 36–106 s. The
  one red evaluation ran 672 s — over ten minutes — before reporting.
- **Session outcomes:** 16 `Advanced`, 3 `AgentError`, **3 `GatesRed`**, 2
  `LimitBackoff`, 2 `Progress`. The engine records "the battery disagreed" as its
  own outcome.
- **Bugs: 1 fixed, 24 open** — the exact inverse of the long build's 40 fixed,
  1 open.
- **Ledger 109: 46 decisions, 44 findings, 13 traps, 6 observations, and zero
  notes.** The long build recorded 66 notes. A run against a subject that
  punishes vagueness writes differently.
- All ten stages `status = 'done'`. `scores` is empty — the evaluation suite is a
  gate, not a scored artefact, and the report never implies otherwise.
- The counting trap again: raw `CheckpointConfirmed` events = 2 against the
  engine's 22.
- Windows: uncapped (24 sessions, 20 checkpoints) and capped at 20M (2 sessions,
  2 checkpoints). Here the window counts **do** sum to the run total — see bug #4.

## Three claims that were corrected before publishing

Written first, checked against the data, then narrowed:

1. "Slowest thing in the corpus by an order of magnitude" — measured **3×** the
   next slowest gate in the same run, and unmeasured across other runs. Now: "by
   a wide margin the slowest thing this run ran", with the comparison against
   the build gate beside it.
2. "Against under a minute for the ordinary build gate" — the build gate takes
   36–106 s. Now: "a minute or two".
3. "The most expensive closing sessions in the corpus" — the engine run's median
   closer (24.9M) is **second** to an abandoned prototype's (40.7M). Its *max*
   closer (52.1M) is the corpus's largest. Now: "the largest session that ever
   closed a checkpoint anywhere in this corpus is this run's, and it cost more
   than twice this run's own median closer — which is itself near the top of the
   range for any completed run here."
