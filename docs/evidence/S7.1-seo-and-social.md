`dist/` that is not on that origin is a red gate.

## What was actually wrong

**The sitemap listed 1 of 21 pages.** `src/pages/sitemap.xml.ts` was the
template's — one entry, the home page, correct for a template with one page and
quietly wrong from the moment this site grew a second. That is worse than having
no sitemap: a sitemap does not say "crawl this site", it says "this **is** the
site", and a crawler that believes it never asks about the other twenty. It is
now built from the collections — home, then each section index followed by its
own entries, in reading order — so adding a concept adds an entry. The path it
publishes is the entry's own `meta.canonical`, which is the same field the
page's `<link rel="canonical">` and its `og:url` come from, which is what makes
the three incapable of disagreeing.

**No page on the site had an `og:image`.** `meta.ogImage` was optional and no
content file set it, so `Base.astro`'s `{ogImageUrl && …}` rendered nothing:
every link to this site posted anywhere rendered as a grey box with a domain
under it. Nothing on any page, in `npm run check` or in the build log showed it.

## The cards

Four 1200×630 PNGs in `public/og/` — `home`, `concepts`, `articles`, `runs` —
and `Base.astro` now hands every page one, by canonical prefix, with
`meta.ogImage` left as the per-page override. No page opts in, so no page can be
published without one.

They are **screenshots of pages this site renders** (`src/pages/og/[card].astro`,
recipe in `docs/OG-CARDS.md`), not art somebody drew, which buys three things:

- the palette comes from `tokens.css` and the sizes from `type.css`, so a card
  cannot drift from the face;
- the words are the section's own `title` and `meta.ogDescription` — the field
  the schema already caps at a card's second line, which is what it was for;
- **the three figures on each card go through `resolveEvidence`**, like every
  other figure on this site. A key the corpus stopped carrying fails the build.

Mocha, pinned with `data-theme="dark"`: a card is one image and cannot follow a
reader's scheme, and a renderer on a machine set to light would otherwise be
served latte through `prefers-color-scheme` — which is how half a set of cards
ends up a different colour from the other half.

Nothing on a card is smaller than 24px. `--overlay` clears the Face's bar at
3:1, and 3:1 is WCAG's bar for *large* text; at 18px the same colour fails. The
card steps are declared together in `type.css` with that floor written down.

### The thing a card does that a page does not: go stale

A card is a *picture of numbers*, taken once, while the numbers underneath it
keep moving. So `npm run seo:cards` records the text each card rendered when the
PNGs were taken (`src/data/og-cards.json`), and `npm run seo` re-renders it and
compares. A harvest that moves a figure under a card turns the gate red and
prints both versions. This is the only figure on the site that is not recomputed
on every build, and it is the only one that needed a manifest to stay honest.

## The gate

`scripts/seo.mjs` / `npm run seo`, run after `npm run build`, checking six
things against `dist/` — one origin, canonicals, the sitemap as the site,
robots.txt agreeing with the sitemap, the cards existing at the right size, and
the cards not being stale.

Every one of those failures is invisible on the rendered page. That is the whole
reason it exists, and it is the same argument the evidence gate makes.

**Proven red eight ways, then green from the restored tree** —
`docs/evidence/S7.1-seo-gate-red.txt` is the gate's own stdout and exit codes,
not a description of them:

| break | caught |
|---|---|
| a page's canonical points at another URL | ✓ (and the `og:url` mismatch with it) |
| a canonical on the wrong origin | ✓ |
| a page dropped out of the sitemap | ✓ |
| robots.txt stops disallowing the card renderer | ✓ |
| robots.txt `Sitemap:` left on the old domain | ✓ |
| an `og:image` PNG that is not 1200×630 | ✓ (read from the IHDR chunk) |
| an `og:image` naming a file never written | ✓ (named per affected page) |
| the corpus moved under a card already taken | ✓ (prints was/now) |

Seven fast checks that do not need a build are in `test/seo.test.mjs`: a section
with no card, a card with no PNG, the `/` fallback moved out of last place in
`OG_CARDS` (a one-line edit that silently gives the whole site the home card),
and the manifest disagreeing with the card list.

## Left for S7.3, filed as a bug

CI calls the fleet's shared `site-ci.yml`, which runs `astro check`, the build
and the three generated-file diffs. It does **not** run this site's own gates —
`evidence`, `anonymity`, `seo`, or the 93 `node --test` cases. They are all
local-only, and a gate that only ever runs on one machine is a gate that rots.
The fix belongs in a second workflow in this repo rather than in the shared one.
