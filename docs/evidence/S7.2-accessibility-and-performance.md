The one failing audit was `color-contrast`, both times, and it took three
passes to clear because each fix moved the complaint rather than ending it.
That is the finding worth keeping:

1. **`--overlay`, 3.36:1 on base and 3.59:1 on the top bar's mantle.** Nav
   links, the theme label, `p.lead` on every concept page, `.aka-label`,
   `.aka-name`.
2. **`--pending`, 2.46:1** — surfaced only once the first was fixed. The "also
   known as" line, the denominator under a rate, the harvest timestamp under
   the evidence strip. `--skipped` is 4.44:1, a near miss on the same ladder.
3. **`--blue` 4.34:1 and `--accent` 4.45:1, latte only** — link text and the
   current section in the top bar, at 18px, which is not large text.

All three are the same mistake: a role the Face holds to *its* bar, spent on a
sentence on a web page. The Face is right — 3:1 is WCAG's bar for 24px text and
1.5:1 is right for a row you skim past in a terminal — and none of the sixteen
roles was changed. What changed is what the site paints text in.

## The three derived tokens

`tokens.css` now carries three tokens that are not roles. Each is a `color-mix`
in srgb of two roles, so it stays inside whichever scheme has won and cannot be
a hex that is right in one and wrong in the other. srgb mix is a plain
per-channel lerp, so `test/contrast.test.mjs` recomputes exactly what the
browser paints rather than trusting a number in a comment.

| token | mix | mocha, on base / mantle | latte, on base / mantle |
|---|---|---|---|
| `--muted` | `--text` 60% (mocha) / 85% (latte) → `--base` | 4.94 / 5.29 | 4.91 / **4.56** |
| `--link` | `--blue` 80% → `--text` | 8.43 / 9.02 | 4.89 / 4.55 |
| `--current` | `--accent` 80% → `--text` | 8.65 / 9.26 | 5.34 / 4.97 |

Two things the numbers show that reading would not:

- **`--muted` needs a percentage per scheme and the others do not.** Mocha's
  text has 11.34:1 of headroom on its own base; latte's has 7.06:1. One
  percentage would have muted one scheme and blinded the other. `--link` and
  `--current` mix toward `--text` rather than away from it, so one number
  serves both.
- **Mantle is the binding surface, not base.** Latte's mantle is *darker* than
  its base, so dark text on it has less contrast, not more — and the top bar
  and the evidence strip are both mantle. 4.56:1 is the tightest figure on the
  site and it is a mantle figure.

The page loses a layer for this: four greys for reading text become two. That
is the right trade. A layer nobody can read is not a layer, and a second muted
token four hundredths of a ratio above the first is a distinction only a
spreadsheet can see.

## Layout shift on the theme flip

Before (session 16): the button showed `Theme` in the markup and `Dark` once
the script ran — 62px to 50px, dragging the whole nav row 12px, CLS 0.00007 —
and `Dark` to `Light` was another 3px on every flip.

After, on `/`, fresh load with cache ignored, then four flips:

```
clsOnLoad            0
entries              0        (no layout-shift entry at all)
clsAfterFourFlips    0
button width         61.516px  ×5 states
nav right edge       1170.484px ×5 states
```

Two passes, and the first one did not work:

- **Sizers for every label except the live one is the tidy-looking version and
  does nothing.** The first thing the script does is overwrite the live label,
  so with `Theme` gone from the document the track shrinks to `Dark` and the
  12px shift is exactly where it was. Measured: 61.5 / 49.8 / 49.8 for
  `Theme` / `Dark` / `Light`. Every candidate is a sizer now, the live label
  included.
- **A centred child still shifts inside a settled box.** With the button fixed
  and the nav still, the label *span* went from 45px to 30px and slid 8px:
  CLS 0.0000054, attributed by the observer's `sources` to that SPAN.
  Stretching the children to the track width and centring the text instead
  leaves nothing with a box that depends on the text in it. That is the
  difference between 0.0000054 and 0.

## The structural gate — `npm run a11y`

`scripts/a11y.mjs`, over `dist/`, after `build`:

```
a11y: 22 readable page(s) each carry a lang, one identified <main>, a working
skip link as their first link, and header/nav/footer landmarks; 289 control(s)
have an accessible name, 0 image(s) declare alt, and no page reorders the tab
order.
```

It exists because contrast is not the half that rots quietly. A skip link whose
target id stops existing, a `<main>` lost in a layout refactor, a `lang` that
goes missing — every one of those is invisible in a browser to anyone not using
the thing it breaks, and none of them shows up in `astro check` or the build.
Lighthouse would catch some of it, on one page, when somebody remembers to run
it. The gate checks all 22 every time.

It found the first real thing it looked at: two `<main>` elements on every page.
The second was its own author's prose — Astro keeps `<!-- -->` comments in the
output, and one in `Base.astro` explaining the skip link mentions `<main>`. The
gate strips comments now. The comments themselves turned out to be 2,632 bytes
on every page of an 18,038-byte page — **14.6%** — so `Base.astro`'s five became
`{/* */}`, which Astro drops. `/concepts/` is 18,038 → **15,406 bytes**, no
other change.
